# Мастерская Desktop Pets

`pet-art` — единый инструмент для добавления моделей, головных уборов,
одежды и готовых комплектов. Он создаёт редактируемый шаблон, проверяет
ресурсы, строит контуры касания, подключает выбор в интерфейсе и показывает
примерку через настоящий QML-рендер утки.

Запускайте `./pet-art` из репозитория либо `pet-art` из любого каталога,
если установлена ссылка в `~/.local/bin/`. Зависимости Python устанавливает
`uv` в отдельное окружение в кеше пользователя, вне папки плагина. `pet-art doctor` покажет доступность
инструментов; для SVG нужен `rsvg-convert`, для примерки — Quickshell,
для импорта `.blend` — Blender.

## Быстрый старт: своя одежда

```sh
pet-art new hat my-cap --label "Моя шапка" --template santa
pet-art new outfit my-coat --label "Моя куртка" --template raincoat
pet-art new look my-look --label "Мой комплект" --hat my-cap --outfit my-coat
pet-art preview my-look --guides
```

Готовая графика появится в `art/packs/my-cap/` и `art/packs/my-coat/`.
По умолчанию создаются варианты для классической и пиксельной утки.
Редактируйте SVG/PNG в этих папках. Каждый пакет содержит **один**
`pack.json`; править QML, JavaScript, списки настроек или контуры не нужно.

```sh
pet-art fit my-cap --model pixel --part hat --rect -30 -64 64 32
pet-art preview my-look --models vector,pixel --guides
pet-art watch my-look --guides
```

`fit` задаёт `X Y ширина высота` в логических единицах. По умолчанию
меняются все три ракурса; `--view side`, `--view threeQuarter` или
`--view front` меняет только один. Доступные части: `hat`, `neck`, `body`,
`sleeve`. Изображение и область касания используют одну посадку.
У рукава используются исходные детали `side` и `front`; примерка в ¾
использует эти же детали на соответствующих крыльях.

`preview` сохраняет лист в `review/art-tool/<ключ>.png`: три ракурса,
три оперения, покой, ходьба, сон, кормление, полёт и перенос. `--guides`
накладывает области касания; `--live` открывает окно примерки. `watch`
следит за файлами пакетов и обновляет этот PNG после изменений, сохраняя
последний рабочий каталог, пока редактируемый файл некорректен.

```sh
pet-art check
pet-art build --install
```

Установка сохраняет настройки, выбранную одежду, коллекцию и резервную
копию предыдущего плагина. `watch my-look --install` применяет каждую
успешную правку сразу. Обычный `build` меняет только ресурсы репозитория.

## Своя модель

```sh
pet-art new model my-duck --label "Моя утка" --base vector
pet-art preview my-duck
```

Базой может быть `vector`, `pixel`, `voxel` или уже добавленная модель.
Для плоской модели копируются 52 части: головы и тела трёх оперений,
стоящие/спящие тела, головы с хохолком и без, крылья, глаза и лапы.
Новая модель появляется отдельной карточкой во вкладке «Внешность».

`geometry` в `pack.json` переопределяет якоря и размеры базового рига.
Неуказанные поля наследуются. Например:

```json
{
  "schemaVersion": 1,
  "kind": "model",
  "key": "my-duck",
  "label": "Моя утка",
  "base": "vector",
  "directory": "model",
  "wardrobeBase": "vector",
  "geometry": {
    "headAnchors": {"side": [78, 64], "threeQuarter": [72, 64], "front": [60, 64]},
    "hatOffset": [-30, -66]
  }
}
```

`wardrobeBase` определяет, чью одежду можно использовать. Пустая строка
выключает наследование одежды. Если силуэт новой модели существенно
отличается, создавайте варианты одежды специально для неё:

```sh
pet-art new outfit my-vest --label "Жилет" --template sailor --models my-duck,pixel
```

У каждого варианта собственные графика, размеры источника и посадка.
Совместимость вычисляется автоматически; в настройках показываются вещи,
которые подходят выбранной модели. Недоступный в текущей модели выбор
сохраняется для возвращения к совместимому варианту.

Все модели используют существующую анимацию: холст **120×112**, три
ракурса и три оперения. Для пиксельной модели источник имеет половинный
размер: тело **60×56**, голова **32×29**, шапка **32×16**. Размеры
остальных деталей указаны в шаблоне. PNG должен быть RGBA; пиксельная
альфа — только 0 и 255. SVG использует `viewBox="0 0 W H"`, обычные
контуры и градиенты; внешние ресурсы, скрипты, CSS и `clipPath` не входят
в поддерживаемый формат. Готовые шаблоны уже соответствуют этим условиям.

## Blender и атласы

```sh
pet-art blender ~/models/my-duck.blend --key my-3d-duck --label "Моя 3D-утка"
pet-art preview my-3d-duck
# После следующей правки мастера:
pet-art blender ~/models/my-duck.blend --key my-3d-duck --label "Моя 3D-утка" --update
```

Импорт сохраняет исходный `.blend` и экспортирует в отдельный пакет.
Требуется совместимый `DuckRig` с семью костями, коллекциями частей,
материалами и Action из [Blender-мастера](../development/blender.md).
Произвольная модель без этого рига требует подготовки в Blender.
При экспорте для библиотеки пропускаются демонстрационные анимации:
отрисовываются только используемые кадры частей.

Дополнительные коллекции `hat.<ключ>` и `outfit.<ключ>` импортируются
автоматически. Пользовательское свойство коллекции `duck_label` задаёт
название в интерфейсе. Экспортированная одежда принадлежит новой модели;
изменения головных уборов в мастере сохраняются вместе с моделью.

Отдельный редактируемый предмет атласной одежды тоже можно создать:

```sh
pet-art new hat my-3d-hat --label "Моя 3D-шляпа" --template explorer --models voxel
```

В такой папке находятся PNG-атлас и `manifest.json` с расположением
кадров. Положение задают `x`, `y`, `width`, `height` в манифесте; `fit`
используется для плоской графики. Контуры пересчитываются по изображениям.

## Передача и удаление

```sh
pet-art export my-cap --output ~/my-cap.zip
pet-art check ~/my-cap.zip
pet-art import ~/my-cap.zip
pet-art remove my-cap
```

Импорт принимает ZIP или папку с `pack.json` в корне, проверяет пакет
до регистрации и не заменяет существующий ключ. Удаление сохраняет
исходники в `.cache/pet-art/removed/`; если на ресурс ссылается другой
пакет, удаление отменяется. Зависимости — базовая модель и предметы
комплекта — должны быть уже добавлены в принимающую библиотеку.

## Встроенная графика и сборка

`art/catalog.json` — единственный редактируемый каталог встроенных
моделей, вещей и комплектов. `art/packs/` — пользовательские пакеты.
`src/PetCatalog.js`, `src/PetLooks.js`, ключи в `src/PetModel.js` и
`src/assets/custom/` генерируются инструментом.

```sh
pet-art build --rebuild-flat
python integration/verify.py
```

`--rebuild-flat` также пересобирает встроенную графику через
`art/flat/build_skins.py`, геометрию и контуры. Это происходит в отдельной
копии проекта с публикацией результата после проверки. Обычный `build`
кеширует контуры по содержимому файла и не запускает повторную обработку
неизменённых ресурсов. Одинаковая сборка не переписывает сгенерированные
файлы. Графика получает адреса по хешу содержимого, чтобы оболочка не
показывала старые текстуры после обновления. Во время работы утки
Python, Blender и чтение изображений для контуров не используются.
